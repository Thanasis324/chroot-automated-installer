AUTOCHROOT IMPLEMENTATION CHECKLIST

Purpose
Implement custom rootfs imports, persistent graphics settings, experimental
GL4ES desktop support.

1. Shared state and installed-distro discovery
- Add shared helpers for chroot-distro discovery.
- Store persistent state outside the managed installer repository at:
  $PREFIX/var/lib/autochroot/
- Store per-distro metadata: install name, package family, setup mode, and user.
- Store per-distro renderer choice in a separate renderer profile.
- Update start, repair, GPU, sudo, and uninstall utilities to list every
  installed chroot, including custom names.

2. Custom rootfs setup
- Add “Custom .tar.gz rootfs” to setup.sh.
- Require a readable local .tar.gz; verify it with tar before installation.
- Ask for a lowercase safe unique install name.
- Ask for base family: Debian, Ubuntu, Fedora, RHEL, or Arch.
- Install using: chroot-distro install <archive> -n <install-name>.
- Ask whether to apply the full Autochroot desktop setup or import only.
- Full setup runs package, user, desktop, audio, and GPU setup using the
  selected base family. Import-only skips those changes and launches as root.

3. Graphics renderer profiles
- Fix GPU detection so Adreno 500-series devices are classified as A5XX.
- Make fix_gpu.sh save the selected renderer in the persistent profile.
- A5XX keeps an explicit choice: Freedreno, Zink/Turnip, VirGL, or LLVMpipe.
- Replace the non-Adreno banner with:
  “Device has Multiple Experimental Recommended Modes”.
- Non-Adreno choices: GL4ES (Recommended Experimental), VirGL
  (Recommended Fallback), LLVMpipe (Software Fallback).
- GL4ES is isolated to its selected desktop session and uses VirGL as backend.
- Never overwrite Mesa’s global/system libGL with GL4ES.
- For every renderer, if desktop startup returns an error or exits immediately,
  print recovery guidance telling the user to run “autochroot config” and select
  “Fix / Update GPU Drivers”.

  those hardware paths verified.
